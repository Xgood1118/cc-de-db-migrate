在现有 mig 骨架上，把它做成一个能安全迁移大表并校验一致性的迁移工具。保留 migrate 与 copy_table 的签名，只用 Python 标准库，不得引入第三方依赖，不得改动 source.db。

## 需要完成

1. **分块迁移**
   - 大表要按主键分块读取（例如每 500 行一批），不能一次 fetchall；内存占用要随批大小有界。
   - 支持断点续跑：每批落到目标库后记录进度，重启从上次成功的主键继续，不重复插入。
   - 支持并发迁移多张表，每张表独立连接，互不干扰。

2. **类型与语义**
   - BLOB 原样迁移，不能被转成字符串；空 BLOB 与 NULL 要区分。
   - TIMESTAMP 文本与 ISO 文本要归一到统一格式；BOOLEAN 的 0/1 与 "true"/"false" 要在目标端落成一致类型。
   - REAL 的空值保持 NULL，不能变成 0.0。

3. **一致性校验**
   - 迁移后逐表比对：行数、主键集合、以及每列内容的校验和（BLOB 与 NULL 要参与计算且能区分）。
   - 校验不一致要指出具体表、具体主键，并以退出码 1 结束。

4. **失败恢复**
   - 单批写入失败要回滚该批，并重试 2 次；仍失败则停止该表、保留已成功的批次与断点，其他表继续。
   - 结束时输出 JSON 统计：每张表的预期行数、实际行数、跳过行数、失败批次数、校验结果。

5. **测试**
   - 覆盖分块读取、断点续跑、BLOB 与 NULL 区分、类型归一、校验不一致检出。
   - `python -m pytest tests -q` 全部通过。

完成后跑一遍 `python -m mig.cli source.db target.db`，确认三张表行数与校验和一致，把输出贴进 README。
